      GPU inference

      Same GPU, same model, same budget. Then measure.

      Open source · llm-serving-bench · Tesla T4

      609 vs 384

      output tokens per second at 64 users, vLLM vs SGLang, on the same GPU, model and memory budget.

      Across 2,048 requests, vLLM's median user waited 1.8 seconds for the first token at 64 users, against 7.4 seconds on SGLang. AWQ 4-bit made single-user decode 2.3x faster but added only 5% throughput at 64 users, because decode is memory-bandwidth bound. Continuous batching did the heavy lifting: going from 1 to 64 users raised vLLM throughput 12x (51 to 609 tokens/s), at the cost of per-user decode slowing from 20 to 92 ms per token. Every prompt was unique and both engines got the same 85% memory (KV cache) budget, so prefix caching could not skew the result.

      Read the write-upHarness on GitHub

      Quinnipiac · SPARK · IEEE UEMCON 2025

      30s → 10s

      average latency for one RAG workload: on-prem GPUs, then GCP L4, then AWS Bedrock.

      30 seconds on our own GPUs, 15 on GCP L4, 10 on Bedrock. The lab moved its inference to Bedrock, even though running those GPUs was my job. The right answer is the one the numbers give, not the one that keeps your cluster busy.

      Llama 3, Mistral, Gemma and DeepSeek at 4-bit on Kubernetes GPU nodes with the NVIDIA GPU Operator and Cilium. CUDA out-of-memory failures kept taking models down, so I put them behind a process-isolated FastAPI server, which eliminated those failures.
